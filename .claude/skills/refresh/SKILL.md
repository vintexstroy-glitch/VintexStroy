# `/refresh` · сверката на цялата верига

Едно пускане = **една сверка вход↔изход** над целия проект. Правило 7 на
проекта важи и тук: партидата завършва със сверка, и **разликата се записва —
дори когато е нула.**

---

## 1 · Кога се пуска

- След резен, който е пипнал решение (нов ADR, сменена дума на собственика)
- Когато нещо се цитира различно на две места
- Преди да се покаже работата на собственика
- Просто защото е минало време — гниенето е тихо

---

## 2 · Веригата · ИЗБРОЕНА ПОИМЕННО

**Това не е „всички файлове". Това е списък.** Миналата ревизия каза „цялата
верига" и пропусна `README.md` — най-разминатия файл в проекта — защото
„веригата" беше дума, а не изброяване. Затова:

| # | звено | какво се гледа |
| :---- | :---- | :---- |
| 1 | **изворите в Драйва** (`ИЗВОР-1` … `ИЗВОР-N`) | **само четене.** Има ли нова дописка, която още не е в решение |
| 2 | `README.md` | входната врата в ГитХъб · дървото на `src/` · командите |
| 3 | `CLAUDE.md` | правилата · продуктите · какво чака решение |
| 4 | `docs/00-CHETI-PARVO.md` | картата · печатът · отворените въпроси |
| 5 | `docs/01` `02` `03` `07` `09` | живите решения |
| 6 | `docs/ADR-*` | решенията в сила |
| 7 | `docs/arhiv/` | **само четене.** Проверява се, че нищо живо не е заседнало там |
| 8 | `.claude/skills/*/SKILL.md` | уменията са част от веригата, не отстрани |
| 9 | `src/` · `app/` | кодът е истината: където той и документът се разминават, **кодът е верният** |
| 10 | `tests/` · `proba/` | доказателството |
| 11 | `.github/workflows/` | пуска ли CI това, което казваме, че пускаме |
| 12 | `package.json` | командите съвпадат ли с описаните |

**Каквото не е в списъка, не е във веригата.** Появи ли се ново звено —
добавя се ТУК, в същия коммит.

---

## 3 · Четирите въпроса на всяко звено

1. **Живо ли е?** Казва какво е вярно СЕГА, или какво се е случило ТОГАВА?
   Второто отива в `docs/arhiv/`.
2. **Дублира ли?** Този факт живее ли и другаде? Ако да — един остава дом,
   другите препращат.
3. **Вярно ли е числото?** Преброй. Не оценявай. (§6)
4. **Има ли тест зад думата?** Документ, който твърди нещо без тест, е
   **бележка**, не спецификация. Пише се в честния списък (`docs/09` §3).

## 4 · Правилото за поправка · НА ЧИСТО

Това е поправка на моя навик, поискана от собственика дословно:

> „Записвай всичко на чисто, а старото в архив, и обяснението да е там, в
> архивираното. Следите не в чистия файл — да не седят неща, които държат
> скрити проблеми и спират оптимизацията."

Значи:

| ❌ не | ✅ да |
| :---- | :---- |
| ⚠ заглавка „заменен" в живия файл | живият файл се пренаписва, все едно грешката не е била |
| „старото пише X, но вярното е Y" | пише се само Y |
| надживян документ до живите | `git mv` в `docs/arhiv/` |
| обяснението в живото | обяснението **вътре в архивирания файл** |

**Редът е задължителен:**

1. **Пренеси живото ПЪРВО** — каквото още важи, отива в живия файл, на който
   му е мястото. Чистка, която архивира преди да пренесе, губи данни.
2. **Напиши защо** — най-отгоре в архивирания файл: кога, защо, с какво е
   заменен.
3. **`git mv`**, не копиране и триене — историята трябва да оцелее.
4. **Изчисти живото от следи.**

Архивът не се редактира. Точно като Журнала.

## 5 · Един факт, един дом

Преписаното число ражда разминаване. Доказано в този проект: „132 проверки"
оцеля на три места, докато истината вече беше 152 — и двете стояха **в един и
същ файл**.

| факт | ЕДИНСТВЕН дом |
| :---- | :---- |
| печатът на изворите (знаци · единици · загуба) | `docs/00` §2 |
| числата на кода и мерките за бързина | `docs/09` §4 |
| бюджетите за бързина (стойността, която чупи) | `proba/merki.test.ts` — кодът |
| редът на резените · генералният план | `docs/03` |
| картата дума→решение→код→тест | `docs/09` §2 |
| правилата, които не се нарушават | `CLAUDE.md` |

Останалите **препращат**. Число извън дома си е находка.

Провери го:

```bash
# всяко число от §4 на docs/09 трябва да се среща ТОЧНО веднъж в docs/
grep -rn "152 проверки\|208 теста" docs/ README.md CLAUDE.md
```

## 6 · Брой, не оценявай

Сгрешавани числа в този проект: два пъти. Затова е правило.

```bash
find src app -name '*.ts' | xargs wc -l | tail -1        # редове код
find tests -name '*.ts' | xargs wc -l | tail -1          # редове тестове
wc -l proba/prohod.mjs proba/merki.test.ts | tail -1     # проход и мерки
ls tests/*.test.ts | wc -l                               # тестови файлове
npm test 2>&1 | grep "Tests "                            # брой тестове
npm run proba 2>&1 | grep "Минали:"                      # проверки в браузър
npm run build 2>&1 | grep gzip                           # големина на пакета
```

## 7 · Сверката вход↔изход · докладът

Всяко пускане завършва с таблица. **Пише се и когато разликата е нула** — това
е смисълът на правило 7: нулата, която е ПРОВЕРЕНА, е различна от нулата, за
която никой не е питал.

```
СВЕРКА НА ВЕРИГАТА · <дата>

звена проверени        12 / 12
поправени               N   (кои)
архивирани              N   (кои, и къде отиде живото)
числа сверени           N   (кои се разминаваха)
думи без тест           N   (в docs/09 §3)
остава отворено         N   (какво и защо не спира работа)

typecheck ✓ · тестове ✓ · проход ✓ · мерки ✓
```

## 8 · Проверката

```bash
npm run typecheck && npm test && npm run proba && npm run merki
```

Сверка, която пипа само документи, **не бива да мърда нито едно от тези числа.**
Мръднат ли — бутнал си код, докато си чистил. Върни се и виж какво.

Плюс:

- `tests/imena.test.ts` — латиница и кирилица не се смесват в дума
- всяка препратка `docs/0X` сочи файл, който съществува:
  ```bash
  grep -ro "docs/[0-9A-Za-z-]*\.md" docs/ README.md CLAUDE.md | sort -u
  ```

---

## 9 · Коммит и push

Коммитът казва **какво е сверено и какво е намерено**, не „обновени документи".
Находката е ценното — тя показва, че сверката е работила.

```bash
git add -A && git commit && git push -u origin <работния клон>
```

---

## 10 · Какво това умение НЕ прави

- **Не пипа изворите.** `ИЗВОР-1-ЧИСТ.md` е печатът на затворената сверка;
  редакция в него чупи одита. Изворите се **допълват** (нов `ИЗВОР-N`), не се
  редактират.
- **Не редактира архива.**
- **Не трие. Мести.**
- **Не изключва червен тест** и не го маркира „ще го оправим после".
- **Не решава вместо собственика.** Отворен въпрос, който чака негово число или
  негов избор, се записва като отворен — не се запълва с предположение.
